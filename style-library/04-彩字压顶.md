# 风格卡：彩字压顶

> **核心画像**：真人实拍底图 + **顶部一行超大彩字标题** + **底部两行白字** + **下半身压一块暗化底带**。三件套缺一不可。
>
> 参考图那个斜体标题是斜切出来的，但**中文粗黑体剪切后每个笔画的方头都会被切出斜口，看着像被削了一刀**。所以默认不斜，`--italic 18~22` 才开。
>
> 和样式02 是亲戚：都是「上下一夹、中间露人」。区别在于 04 把标题**做大、做斜、上色**，并且给底部加了一条**暗化底带**——白字不再靠阴影硬撑，而是自带一块深色地基。所以 04 能扛住高光底图（白墙、亮天、浅灰棚），02 扛不住。

```yaml
name: 彩字压顶
aka: 斜字压顶（旧名，2026-11 起默认不斜）
status: active
category: 真人实拍 + 顶部彩字斜切大标题 + 底部两行白字 + 暗化底带

fits:
  - 有强概念的短标签（2-6 字），需要一眼砸进眼睛里
  - 底图偏亮 / 偏杂（白墙、浅灰棚、外景高光），白字需要一块暗底才站得住
  - 人物在画面中下部、头顶有留白的自拍或实拍
  - 缩略图竞争激烈的位置：首页首图、投放素材、瀑布流

# —— 不可变内核 ——
core:
  layout: 顶部 1 行标题 + 底部 2 行白字，共 3 行（标题只能 1 行，底行 2-3 行）
  title_edge: 标题贴顶，字的下沿可以压到额头，但不下探到眼睛
  italic: 斜切可选，默认关闭（中文剪切后笔画端会出斜口，像被削）
  backdrop: 底部必须有一条暗化底带 —— 这是本卡的身份证
  no_deco: 角标 / 订阅按钮 / 姓名条 / 播放键等所有 UI 装饰一律不做，只留两处文字 + 底带
```

## 三条识别特征

1. **彩字压顶**：标题是整张唯一上色的元素，默认参考图实测的亮蓝 `#4490DC`。一头撞在白墙、灰底、深色衣服上都能跳出来——这是它比样式02 更抓眼的根本原因。想更凶换 `#FF3B30` 红或 `#FFD400` 黄。
2. **底部一条暗化底带**：0.55 H 以上**一点不压**，以下按幂函数加深，颜色是**深蓝黑**（`#0E2352`）而不是纯黑。压过之后底图下半身整体变冷变暗，白字像贴在深色地面上。纯黑会把底图的皮肤压成脏灰。
3. **一行大、一行小**：末行撑满 90.5% W，上面那行只撑 80% W；两行还用同一个左基线，读起来是「平铺一句 → 加大落点」。

## 参数（相对画布，换画布也成立）

```
canvas:     3:4（1080 × 1440），全库统一
title_w:    0.860 W     # 标题墨迹宽度，硬约束（斜切后的实际墨迹宽）
title_inset:0.050 H     # 标题墨迹顶边 → 画布顶
italic:     0           # 默认不斜；18~22 复刻参考图的斜体感，别超过 24
bot_w:      0.905 W     # 底行【末行】墨迹宽度（落点）
bot_lead_w: 0.800 W     # 底行【前几行】墨迹宽度（引导，小一档）
bot_inset:  0.045 H     # 末行墨迹底边 → 画布底
line_gap:   0.018 H     # 底行之间空隙（参考图两行贴得紧）
bot_left:   0.038 W     # 底行左对齐的左边距
size_range: 0.055 W ≤ 字号 ≤ 0.420 W

# 底带
veil_color: #0E2352     # 深蓝黑；不要用纯黑
veil_peak:  205/255     # 最浓处（白底图必须到 190+ 白字才站得住）
veil_top:   0.55 H      # 这条线以上 alpha=0，一点不压
veil_curve: alpha = peak × t^0.80   # t 从起点到画布底的归一化距离
veil_auto:  (0.66 H 以下均值 - 80) × 2.4，夹在 60~205 之间

# 底行字号天花板
bot_cap:    0.85        # 底行字号 ≤ 标题字号 × 0.85
                        # 不设这个，4 个字的短句撑满 0.905 W 会比标题还大，主次立刻颠倒

# 标题阴影：只有一层右下柔影，不加暗晕（暗晕会糊掉细笔画和斜切边）
title_shadow: 偏移 0.0022 W / 0.0088 H，模糊 0.0039 W，黑 175/255
# 底行阴影：暗晕 + 实影，同样式02
halo:   模糊 0.0036 W，黑 145/255，无偏移
shadow: 偏移 0.0016 W / 0.0055 H，模糊 0.0030 W，黑 210/255
```

## 配色

| 位置 | 默认 | 说明 |
|---|---|---|
| 标题 | `#4490DC` 亮蓝 | 参考图实测 (68,144,220)。要更凶可换 `#FF3B30` 红 / `#FFD400` 黄 |
| 底行 | `#FFFFFF` 白 | 不换。白字压暗带是本卡的对比结构 |
| 底带 | `#0E2352` 深蓝黑 | 不要用纯黑 `#000000`，会把肤色压脏 |

标题色一换，底带色也要跟着往同一色相偏一点点（蓝配深蓝、红配深酒红），整张才不会两块打架。

## 用法

```bash
# 手动分行：第一段是顶部大标题，后面都算底部文字
python tools/style04_title_band.py --base 底图.png --out 封面.png \
  --split "隐藏天赋|如何用 AI 找到|属于自己的天赋"

# 只给标题和底部整句，底部自动断两行
python tools/style04_title_band.py --base 底图.png --out 封面.png \
  --top "隐藏天赋" --bottom "如何用 AI 找到属于自己的天赋"

# 换色 / 去掉斜切 / 底带加满 / 底行居中
... --title-color "#FF3B30" --veil-color "#2A0A12"
... --italic 0            # 不要斜切
... --veil 200            # 底带拉满
... --title-w 0.82        # 标题贴边时收窄
... --bot-cap 0.75        # 底部短句再压小一档
... --align center        # 底行改居中
```

脚本流程：裁 3:4 → 按底图亮度算底带强度并压底 → 标题二分反解字号（**含斜切后的实际墨迹宽度**）→ 斜切 → 贴顶居中 → 底行逐行反解并按「末行大、引导行小」自下而上堆叠、左对齐 → 双层阴影 → 输出。跑完打印每行字号、墨迹尺寸、宽占比和 y 位置。

## 不要做

- **不要默认开斜切**。中文字是方的，剪切后竖笔变细、横笔变粗，所有方形笔画端头都被切成斜口——放大看像被削过。参考图是斜的，但那是因为它字少（4 字）、字重没到 900；7 字以上再斜会碎。要试就先 `--italic 18`，别一步上 28。
- **不要给标题加黑描边**。那是样式01。04 靠颜色和柔影分离，不靠描边。
- **不要把底带做成硬边色块**。硬边就是样式03 的白条换了个颜色，整张会像贴了张纸。必须是上沿渐隐的软过渡。
- **不要用纯黑做底带**。纯黑会把底图肤色压成灰绿，人物看着像遗照。要带蓝。
- **不要加角标 / 订阅按钮 / 姓名条**。参考图上那些是平台 UI，抄进来就是廉价感。
- **不要把标题塞成两行**。两行标题会吃掉 0.35 H，人只剩半条命。标题超过 6 字就换更短的词眼，长句交给底部。
- **不要在深色底图上把底带开到 200**。底带是给亮底图兜底的，深底图 `--veil auto` 会自己降到 60。

## 踩坑记录

- **斜切必须用变换后的实际墨迹宽度反解字号**。计算式 `w + tan(θ)·h` 只是估算，中文不同字的墨迹高度不一样，估算和实绘能差 4-6%。做法和第二点一样：先二分、再实绘回修 3-4 次。
- **`Image.transform` 的输出尺寸必须包含扩展区**。写成 `transform((w, h), AFFINE, (1, -k, extra, 0, 1, 0))` 时，右移的部分会被直接切掉，字看起来像被削掉一截——输出要用 `(w + extra, h)`。这个 bug 表现为「左边第一个字缺一块、右边最后一个字被裁」，很容易误判成居中算错。
- **斜切角度超过 24° 会失真**。中文字身是方的，剪太狠笔画会拉成斜条，18~22° 还像正常的斜体，30° 以上只适合英文。
- **斜切后笔画粗细会变**。shear 只做几何变换，不做光学补偿：竖笔被压细、横笔被拉粗。粗黑体 900 字重下最明显，笔画端部的方头会变成斜切口——这就是「字被削了一块」的观感来源，不是裁切 bug。
- **标题不能加暗晕**。样式02 那双层阴影挪过来会把斜切边的抗锯齿糊成毛边，蓝字看着发脏。标题只要一层右下柔影。
- **底带起点不能太高**。一开始用 0.46 H 起渐隐、上一路斜下来，白底图（白墙白衣服）会被整张蒙上一层灰蓝，人物全脏。起点以上必须 `alpha = 0`，0.55 H 是最稳的位置：腰部以下压、以上不动。
- **底带起点也不能太低**（0.68 H 以下），那样第一条底行会压在没有暗带的亮底上，只剩阴影硬撑。
- **`veil auto` 只看 0.66 H 以下**。看整张图均值会被上半部高光骗过去：人物头顶白墙一亮，算法以为整张很亮，底带就压过头；反过来，画面里有深色镜框、地面又会拉低均值，白裙子上的白字就废了。
- **短句必须设字号天花板**。`三个建议` 4 个字撑 0.905 W 时字号会到 249，比 7 个字的标题（203）还大，主次直接颠倒。`--bot-cap 0.85` 按标题字号做上限，短句自动收窄、留白。
- **底行两行字数差不要超过 2 字**。这套逻辑是「每行独立撑满目标宽」，7 字配 4 字时字号差 20%+，看着像两句不相干的话。文案尽量对成 6/8、7/7 这种。
- **底行左对齐要设上限**。`x = min(0.038 W, W - 字宽 - 0.02 W)`，否则长行会顶出右边界。
- **中英混排的空格会撑开字距**。文案写「如何用AI找到」比「如何用 AI 找到」更紧凑——中文排版里英文两侧不需要手动加空格，加了会在放大后变成明显的洞。
