# 风格卡：黄条压字

> **核心画像**：真人实拍底图 + **三件套卡在画面下部**——白字身份行、柠檬黄实色横条压黑字、白字副标题（关键词换成同一个黄）。三件套缺一不可。
>
> 和样式03「白条压字」是远亲，但气质完全相反：03 是白条黑字、书面冷静；05 是黄条黑字 + 彩色高亮词，喊话、有攻击性、专门抢注意力。

```yaml
name: 黄条压字
aka: 黄底黑字 / 黄色横条 / Yellow Bar
status: active
category: 真人实拍 + 白字身份行 + 黄条黑字主标题 + 白字副标题（关键词高亮）
```

## 一眼认出它

1. **一条柠檬黄实色横条**（`#FAE04B`，实测自参考图），横切画面下部 0.55–0.70 H 区间。
2. **黑字比黄条宽，字咬出条外**。这是本卡的身份证——黄条只是"字底下垫的一块色"，不是"装字的框"。黑字两端压在底图上，靠黑度硬扛。
3. **上方一行白字身份行**，黑描边，讲"这话谁说的"（某某专家 / 某个机构 / 某类人）。
4. **下方一行白字副标题**，黑描边，其中**一到两个词换成黄条同色**（`--hl`）。这个高亮词是整张图的钩子。
5. 三行全部**居中**，不用左对齐。

## 适合什么

- 干货/知识类口播封面，"权威背书 + 一个反常识结论"的句式
- 例句：`斯坦福神经科学家：` / `早晨去晒太阳` / `一个最被低估的习惯`
- **主标题 4-6 字，身份行 8-12 字**。这个字数关系是这套样式的骨架，反了就不成立（见下面「字数决定一切」）
- 需要在小红书瀑布流里靠颜色直接跳出来的位置
- 底图可以是深色（人物穿深色衣服、暗棚），黄条在白/黑背景上都成立

## 不适合什么

- 底图本身已经很花（黄条会吃掉复杂度，画面变吵）
- 文案没有"身份 + 结论"结构，硬凑三行会很假
- 想要安静、高级感的封面 → 用 03

## 不可变内核

```yaml
core:
  structure: 身份行(白) → 黄条(黑字) → 副标题(白+黄高亮)，三行，顺序不许换
  bar_overlap: 主标题墨迹必须比黄条宽，字咬出两侧（bar_scale < 1）
  highlight: 副标题必须有高亮词，颜色 = 黄条色，一行为一到两个词
  align: 三行全部居中
  no_deco: 播放键 / 进度条 / 角标 / 台标一律不做
  canvas: 3:4
```

## 参数（相对画布）

```yaml
canvas:      3:4（1080 × 1440），全库统一
id_w:        0.860 W     # 身份行墨迹宽，硬约束
ink_w:       0.920 W     # 主标题墨迹宽【上限】（故意大于黄条）
ink_max:     0.148 W     # 主标题字号【上限】≈160 号 ← 真正管住"字太大"的是这个
id_max:      0.118 W     # 身份行字号上限 ≈127 号
bot_max:     0.126 W     # 副标题字号上限 ≈136 号
bot_w:       0.930 W     # 副标题墨迹宽，硬约束（最宽的一行）
bar_scale:   0.950       # 黄条宽 / 主标题墨迹宽。<1 = 字咬边，这是特征；=1 会变成规整的色块
bar_h:       1.42        # 黄条高 / 主标题墨迹高
bar_cy:      0.620 H     # 黄条中心 y，整块文字绕它上下排
gap_id:      0.024 W     # 身份行墨迹底 → 黄条顶
gap_bot:     0.024 W     # 黄条底 → 副标题墨迹顶
stroke:      0.065       # 白字黑描边 / 字号
id_cap:      0.80        # 身份行 ≤ 主标题 × 0.80（只兜底，主控是 id_max）
bot_cap:     0.88        # 副标题 ≤ 主标题 × 0.88（只兜底，主控是 bot_max）
yellow:      #FAE04B     # 黄条与高亮字同色，实测自参考图
shadow:      偏移 0.0050H，模糊 0.0028W，黑 120/255（底图偏暗，不能压太重）
```

**字号是变量，宽度是常量**。三行各自撑满自己的目标宽，字数一变字号就跟着变——这样每张封面的文字面积是一致的。

**三行各有一个绝对字号上限，互不联动**。这是第三版改法，前两版都错：

| 版本 | 做法 | 结果 |
|---|---|---|
| v1 | 只按宽度反解，不设上限 | 4 字主标题放到 235 号，黄条厚成路障 |
| v2 | 上下行按「主标题 × 比例」 | 主标题一大，上下行跟着膨胀，底行撑到 93%W 撞边 |
| v3 | 每行一个绝对上限（`ink_max` / `id_max` / `bot_max`） | 主标题封在 160，上下行锁在 127 / 136，宽度自己收 |

现在的比例参数（`id_cap` 0.80 / `bot_cap` 0.88）只当兜底：主标题极小时别再压上下行，主标题极大时别让上下行反超。主控永远是那三个绝对上限。

**主标题字号范围 145-171 号（0.134-0.158 W），默认 160。** 低于 145 大黄条太薄、字压不住画面；高于 171 就回到"中间一块砖"的老问题。

## 用法

```bash
# 标准三行
python tools/style05_yellow_bar.py --base 底图.jpg --out 封面.jpg \
  --id "斯坦福神经科学家：" \
  --ink "早晨去晒太阳" \
  --bot "一个最被低估的习惯" --hl "低估"

# 高亮多个词
... --hl "低估|习惯"

# 副标题拆两行
... --bot "一个最被低估的|日常习惯" --hl "低估"

# 换配色（黄条与高亮字同时变）
... --yellow "#FF5A3C"        # 橙红
... --yellow "#9BE15D"        # 青柠

# 不要身份行
... --id ""

# 整块上下挪
... --offset-y -40
```

脚本流程：裁 3:4 → 主标题二分反解字号（黑字无描边）→ 身份行与副标题按主标题字号 × cap 反解 → 黄条按主标题墨迹宽高生成（居中）→ 压黄条 → 压三行字 → 白字投影 → 输出。跑完打印每行字号、墨迹尺寸、宽占比和 y 位置。

## 不要做

- **不要把黄条做成"装字的框"**。黄条一旦比字宽，就退化成样式03 的白条换了个颜色，冲击力全没。
- **不要给黑字加白描边**。黑字压在黄条上，对比已经拉满；加描边只会让笔画糊成一团。
- **不要让副标题没有高亮词**。高亮词是这个样式唯一的"语气重音"，去掉就是三行平铺的白字。
- **不要三行都用同一个字号**。主标题必须明显大于上下两行，否则读起来像三句并列的话。
- **不要用高饱和纯黄 `#FFD400`**。参考图那个黄是偏奶的柠檬黄，纯黄在深色底上会泛荧光、看着廉价。
- **黄条宽度由字数决定，这一步没法用字号救**。主标题 4 字 → 黄条 55%W；6 字 → 87%W。要让黄条占满下半身，就把主标题写成 6 字（`给00后的建议`），别把 4 字放到 200 号以上硬撑。
- **主标题不要超过 7 字**。8 字以上主标题会小到跟身份行差不多，三行层级直接塌掉——实测 9 字主标题字号 121，身份行 105，几乎一样大。宁可在身份行里多写字，也不要把长句塞进黄条。
- **主标题不要少于 4 字，而 4 字本身也别用**。这是本卡最硬的一条死锁：主标题 4 字想撑到 82%W，字号必须到 227，而身份行只有 112 号——**层级比 1.97，参考图是 1.25**；三行会结成一坨，黄条 316px 厚成色块，底行被顶到 88.5%H 贴画布边。反过来守住字号上限，4 字就只剩 55%W 的黄条，中间细腰、上下台阶。
  两条路都死，因为它同时被"宽度"和"层级比"两个约束夹住。**字数少 ≠ 字要大，而是这条卡不接 4 字主标题**。实测对照（同一底图、同一身份行）：

  | 主标题字数 | 字号 | 主标题/身份行 | 黄条宽 | 结论 |
  |---|---|---|---|---|
  | 4 字（`一键生成`） | 160（封顶） | 1.39 | 55.2% | 细腰，上下台阶 |
  | 4 字（硬撑） | 227 | **1.97** | 84.1% | 字压画，三行结块 |
  | 6 字（`你想要的模特图`） | 139 | **1.24** | 84.8% | 成立 |
  | 7 字（`一键生成模特图`） | 145 | 1.25 | 87.4% | 成立 |

  踩坑来源：文案「最近超火的AI图库，一键生成你想要的模特图」，按原文断句成 `一键生成` 做黄条，两版都难看。**正确做法是重新断句，不是调参**——把主标题换成能装 6-7 字的那半句（`你想要的模特图`），动作和保证挪到副标题（`一键生成，全都有`）。封面文案要迁就版式，逐字照搬原句是错的。
- **不要把黄条挪到画面上半部**。它要压在下半身，上半部要留给脸和头顶。
- **不要做播放键 / 进度条 / 台标**。参考图上那些是平台 UI，抄进来就是廉价感。

## 踩坑记录

- **字号回修的上限不能用二分收敛后的 `hi`**。二分把 `hi` 一点点收到目标字号，回修时再拿它当 `min()` 的上限，就等于"只许往下调、不许往上补"，目标宽永远差 6-7%。必须先存 `hi0 = hi` 再做二分。样式04 里有同一个 bug，一并修了。
- **描边要分两遍画**：先整行只画描边（`fill=(0,0,0,0)` + `stroke_fill=黑`），再逐字填色。一遍画完的话，高亮黄字的描边会在接缝处被相邻字盖掉，出现缺口。
- **行内高亮用逐字定位**，不要用 `textlength` 切段。中文字宽一致但全角标点（`，：！`）会偏窄，切段累加会错位半字。
- **`bar_h` 按"主标题墨迹高"算，不是按字号**。中文墨迹高只有字号的 0.8 左右，按字号乘 1.42 黄条会太高，字上面会空掉一大截。
- **身份行的全角冒号会让右边显得空**。`斯坦福神经科学家：` 的墨迹重心偏左，靠 `getbbox()` 居中是准的，别手动往右挪。
- **这一套全是"宽度反解"，所以字数决定一切**。主标题 4 字和 9 字，字号能差一倍，黄条厚度也跟着变。写文案时先看主标题字数，再决定身份行要不要补内容——这是这个样式唯一需要动脑的地方。
- **主标题字多时身份行会被 cap 压成一小团**。已加兜底：身份行墨迹撑不满 0.62 W 就放宽 cap 重解，但放宽后层级会变平，属于补救不是解法。
- **底图很亮时白字会飘**。这张卡没有暗化底带（那是 04 的做法），亮底要靠 `--stroke 0.075~0.085` 加粗描边硬扛，或者换深一点的底图。
